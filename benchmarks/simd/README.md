# SIMD investigation tools

The durable [investigation report](../../Research/2026-10-18-simd/REPORT.md) defines the objective, prospective gates, complete budgets, dispositions and limitations. Raw data is in [results/simd](../results/simd). This is a controlled external CoreCLR study using DotNetLab diagnostics, not qualified ReJIT promotion. The original source has not been changed at the pending adoption gate.

`driver.py` owns the shared host mutex, serial randomized processes, fixed affinity, runtime selection, implementation/caller hashes and exact-ID validation. `candidates.py` generates experimental sources from the frozen baseline or a named predecessor. `profile.py` uses an owned persistent DotNetLab MCP controller, bounded CLI observation grants, operation polling and verified trace artifacts. `validate.py` builds/tests/packages the repository with disposable artifacts confined to the task directory. `archive.py` retains inputs and verifies their hashes before cleanup.

The reproduction archive and its manifest are under `Research/2026-10-18-simd`. They preserve frozen source snapshots, actual measured caller/library assemblies, native executables, fixture files, pinned native source archives and selected build/test evidence. The original caller predates an independently added benchmark guard branch; preserved binaries and protocol hashes are authoritative for historical timings. The warmed caller's exact source is also retained. Catalog policies, signing files, caches and unrelated process inventories are excluded.

To inspect a historical assembly, extract the archive into a **new dedicated directory under `D:\Workspaces\AI`**, verify its manifest, and select the corresponding `*-worker/Bench.dll`. Invoke with `dotnet exec --fx-version 10.0.13` and the recorded command from `launches.json`. Generic-worker arguments are dimension, coordinate type, entry count, distribution, API mode, and optional action. Examples: `2 double 100000 uniform original codegen` or `3 int 100000 clustered plain codegen`. A normal measurement uses no final action. The file-worker takes the recorded fixture path. Native comparison needs the explicit `PACKED_NATIVE_PATH` recorded by the driver.

For a new study, configure the scripts' task root and **new durable evidence destinations**, declare its budget and gates, then build/stage the chosen frozen source with `driver.py build <stage>`. Existing result folders and code listings deliberately refuse overwrite; do not delete historical observations to make a new run fit. `driver.py confirmation <stage>` selects the historical global candidate; the `final-confirmation <stage>` alias substitutes the named source and uses a separate seed/output directory. In this investigation `final-tiered` was used only for the prespecified three-second warmed global comparison. Other final aliases were prepared but not executed. A repeat or different runtime/fixture is a new epoch, not additional evidence retroactively added to a completed budget.

Dependencies are SDK 10.0.402, runtime 10.0.13, Windows x64/Python, plus the pinned local DotNetLab host for profiling. Native reproduction also requires Rust/MSVC/Windows SDK; `native.ps1` contains this host's exact paths and flags. Those installation paths are not portable defaults. Review fetched build hooks and resolved effects before compiling. Timing here excludes process startup/JIT diagnostics, includes result materialization and consumption, and does not establish significance, per-request percentiles, PMU behavior, multicore scaling or portability of the measured gain.
