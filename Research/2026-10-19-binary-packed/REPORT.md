## Disposition and limits

The concrete proposal is an immutable 2D-double PackedRTree<T>, existing mutable/snapshot/concurrent types sharing read contracts, and mutation contracts on the three plain mutable types. It retains flat owned bounds/values, scalar recursive pruning and contained-subtree copying. Construction uses guarded four-box AVX normalization plus eight-key vector Hilbert encoding, with exact scalar fallback, original comparison/radix ordering and workspace ownership. Only the private recursive helper requests immediate optimized JIT code and prevents inlining; the public entry and application retain ordinary tiering. This sacrifices tier-dependent PGO on that helper and may affect cold first-query compilation; cold startup is not measured here.

Binary partitions, owned-swap builders, output-buffer writing, alternate predicate orders, iterative traversals, packed-64 sorting, vector bound reductions and normalized-box layouts do not pass their declared adoption gates. Their source/results remain available. The proposal passes its independent finite-matrix guards and wins nine external comparison cells, but still loses three small-tree cells. It does not establish a universal algorithm, statistical significance, p99, other-CPU performance, or exhaustive registry coverage. The materialized caller also includes consumption cost: retained .NET Query code has scalar checksum enumeration; this follow-up has no emitted native Rust inspection, so do not attribute the remaining difference to LLVM auto-vectorization as an established fact.

Potential follow-ups require new protocols: exact struct visitation/span-output APIs and true batch-query kernels (different caller contracts must be reported separately), alternative spatial representations such as grid/kd/Morton construction with distribution/query guards, and native/AOT comparisons with their own deployment/runtime qualification. These are untested here, not presumed speedups or retroactive best-of-cell dispatch.
